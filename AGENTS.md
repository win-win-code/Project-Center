# AGENTS.md

## Область действия

Эти инструкции применяются ко всему проекту `Project Center`.

## Назначение проекта

`Project Center` — нативное macOS-приложение на Swift/AppKit для просмотра
состояния локальных Git-репозиториев и запуска общих `just`-рецептов Push/Build.
Проект не использует Xcode-проект или Swift Package Manager: приложение
компилируется напрямую скриптом `build.sh`.

## Основные файлы

- `main.swift` — весь код приложения, UI, Git-диагностика, запуск команд и поиск
  артефактов.
- `projects.json` — список управляемых проектов и соответствующих `just`-рецептов.
- `Info.plist` — метаданные macOS bundle и минимальная версия macOS.
- `build.sh` — сборка, подпись и атомарная замена локального
  `Project Center.app`.
- `Project Center.app/` — сгенерированный локальный артефакт, а не источник
  истины.

## Сборка и проверка

После изменений исходников выполняйте:

```sh
./build.sh
```

Сборка требует macOS с Xcode Command Line Tools. Скрипт компилирует приложение
для Apple Silicon (`arm64`) с deployment target macOS 13.0, проверяет
`Info.plist`, подписывает bundle ad-hoc и валидирует подпись.

Для изменений только в конфигурации сначала проверяйте JSON:

```sh
plutil -lint projects.json
```

Если менялись `main.swift`, `Info.plist`, `projects.json` или `build.sh`, итоговая
проверка всё равно должна включать полный запуск `./build.sh`.

Автоматических тестов сейчас нет. Для изменений поведения дополнительно
проверьте вручную:

1. приложение запускается;
2. статусы всех карточек обновляются без зависания UI;
3. Push/Build запускаются последовательно и полный stdout/stderr появляется в
   панели логов;
4. ошибки Git, `just`, Docker и отсутствующих артефактов показываются понятным
   сообщением;
5. кнопки «Запуск» и «Место» выбирают самый свежий существующий артефакт.

## Правила внесения изменений

- Сохраняйте совместимость с macOS 13.0 и AppKit; не добавляйте API, доступные
  только в более новых версиях, без проверки availability.
- Не добавляйте Xcode-проект, SwiftPM или сторонние зависимости без явной
  необходимости.
- Тяжёлые Git/build-операции должны выполняться вне main thread; обновления UI —
  только в main queue.
- Всегда дренируйте stdout/stderr дочернего процесса до ожидания его завершения,
  чтобы не получить deadlock на заполненном pipe.
- Не добавляйте auto-commit, force-push, автоматическое переключение веток или
  изменение рабочего дерева управляемых репозиториев.
- Push должен оставаться заблокированным для detached HEAD, репозитория без
  коммитов и репозитория без `origin`.
- Для составной операции `Push + Build` прекращайте цепочку после первой ошибки.
- Пользовательские строки интерфейса и сообщения об ошибках пишите по-русски;
  имена Swift-типов, методов и переменных — по-английски.
- Сохраняйте текущую однопоточную очередь операций: одновременно выполняется не
  более одной операции, а на время её выполнения действия UI блокируются.
- Не редактируйте файлы внутри `Project Center.app` вручную. Меняйте исходники и
  пересобирайте bundle через `./build.sh`.

## Формат `projects.json`

Каждый элемент массива обязан содержать:

```json
{
  "name": "Название в UI",
  "path": "/абсолютный/путь/к/проекту",
  "pushRecipe": "just-рецепт-push",
  "buildRecipe": "just-рецепт-build",
  "buildLabel": "Подпись кнопки",
  "artifactPaths": ["relative/path.app", "dist/*.dmg"]
}
```

- `path` — абсолютный путь к локальному проекту.
- Имена рецептов должны существовать в общем
  `~/My soft/justfile`.
- `artifactPaths` задаются относительно `path`, но абсолютные пути также
  поддерживаются.
- В компонентах путей поддерживаются маски `*` и `?`.
- Пустой `artifactPaths` допустим для проектов без запускаемого/открываемого
  артефакта.
- При изменении `projects.json` сохраняйте ту же копию в собранном bundle через
  полный запуск `./build.sh`.

## Архитектурные ориентиры

- `ProjectDefinition` должен соответствовать схеме `projects.json`.
- `CommandRunner` — единая точка запуска внешних процессов и сбора результата.
- `operationQueue` сериализует длительные операции.
- `readSnapshot(for:)` только читает состояние Git и не должен изменять
  репозиторий.
- `detectVersion(in:)` ищет версию в `Info.plist`, JSON, `pyproject.toml`, теге и
  затем в SHA; сохраняйте этот порядок fallback.
- `latestArtifact(for:)` выбирает существующий артефакт с самой новой датой
  изменения.

При добавлении новых возможностей предпочитайте небольшие локальные изменения в
существующей структуре. Если `main.swift` станет заметно сложнее, разделяйте его
по ответственности без изменения пользовательского поведения.
